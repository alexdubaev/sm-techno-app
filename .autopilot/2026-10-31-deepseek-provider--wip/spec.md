# Подготовка DeepSeek

## Реализация

Добавить реальный HTTP-адаптер DeepSeek Chat Completions на фиксированный официальный HTTPS endpoint. Модель deepseek-flash поддерживает текст и изображения. Пользоваться существующим DocumentSourceReader: Office/PDF/Excel извлекаются/рендерятся до API, изображения отправляются inline, без публичных URL и удалённого хранилища файлов. Никаких model tools.

Одна фабрика выбора используется DocumentAssistantService и временной расценкой Остатков. Существующая инъекция extractor в сервисе сохраняется. CodexDocumentExtractor остаётся доступным и поведением по умолчанию для совместимости. Общие prompt/валидация переиспользуются только в нужном объёме. DeepSeek получает строгий JSON-запрос, но JSON mode не гарантирует схему: локально проверять форму, значения, отсутствующие поля; отвергать пустой/оборванный ответ, tool calls и невалидные поля. Provenance указывает фактическую модель DeepSeek.

## Конфигурация

DOCUMENT_ASSISTANT_PROVIDER=codex по умолчанию; явный deepseek включает новый адаптер. DEEPSEEK_API_KEY пуст в .env.example; модель DOCUMENT_ASSISTANT_DEEPSEEK_MODEL=deepseek-flash, общий существующий timeout. Никаких реальных ключей, сетевых платных вызовов, авторизации, новых аккаунтов, доступа к локальному Codex auth. Секрет остаётся backend-only в окружении сервиса. Никакого автоматического fallback между провайдерами. Ошибки конфигурации/HTTP/таймаутов/лимитов дают безопасные понятные сообщения без тела ответа, токенов, документов или путей.

Ограничить размер входа и HTTP-ответа, общий срок запроса; не следовать redirects с Authorization; TLS verification включён. Не наследовать неявные прокси. Нет настраиваемого произвольного production endpoint. Допустима ограниченная инъекция transport в тестах для локального HTTP stub без реального API. Новые зависимости не нужны: stdlib или уже установленные библиотеки.

## Границы

Не менять public API/schema/migrations/1С/ACL, сохранение документов, менеджерское подтверждение, шаблоны, номер спецификации и поиск остатков. Временная расценка остаётся без базы/КП/клиента. Не менять frontend и схему Docker/серверов. Существующий compose env_file уже передаёт backend env. Не монтировать ключ во frontend и не добавлять его в ответы настройки/логи.

## Приёмка

Локальный настоящий HTTP stub проверяет запрос и ответы адаптера: ведущие нули, реквизиты/счёт, изображения, формат JSON, ошибки auth/rate-limit/timeout/oversize/malformed/truncated/tools. Проверить фабрику и оба потребителя, режим без ключа без network/runtime, прежние extraction/document/stock проверки на изолированных данных. Один независимый security review нового outbound/secret boundary; исправить только подтверждённые замечания и узко перепроверить. Реальный DeepSeek inference явно NOT RUN до ключа. Перед публикацией проверить триггеры, PR merge только проверенного исходника. Этот этап завершён после интеграции кода; сервер не переключать и прежний PR13 runtime gate не обходить.

Источники API: https://api-docs.deepseek.com/guides/vision/ и https://api-docs.deepseek.com/guides/json_mode . API-совместимость не является доказательством реальной точности модели.
