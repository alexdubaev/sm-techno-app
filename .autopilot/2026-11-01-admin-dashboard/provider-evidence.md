# DeepSeek — проверенные возможности 2026-11-01

Только официальные публичные документы, без обращения к ключу/аккаунту владельца.

- https://api-docs.deepseek.com/api/get-user-balance/ — GET /user/balance, is_available, balance_infos (currency, total_balance, granted_balance, topped_up_balance). Это текущий баланс аккаунта, не история расходов приложения.
- https://api-docs.deepseek.com/quick_start/token_usage/ — точный расход берётся из usage ответа API. Оценка длины текста не заменяет usage.
- https://api-docs.deepseek.com/api/create-chat-completion/ — текущий chat/completions endpoint и usage. Не менять существующую обработку документов ради аналитики.
- https://api-docs.deepseek.com/quick_start/rate_limit/ — ограничения конкурентных подключений на уровне аккаунта; 429 при превышении. Документированный общий предел не доказывает фактическую персональную квоту, а локальная история запросов не показывает нагрузку других приложений аккаунта.

Вывод: хранить только безопасные числовые метрики приложения с явной датой начала учёта. Баланс отдельно, в валюте провайдера; не вычислять точную стоимость из разницы балансов (есть пополнения, другие приложения). Не рисовать исторический процент квоты без известного знаменателя. Ошибки API баланса не должны блокировать продажи или OCR.
