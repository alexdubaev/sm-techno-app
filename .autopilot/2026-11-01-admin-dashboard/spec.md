# Спецификация: обзор компании для администратора

## Задача
Администратор при входе должен видеть продажи всей компании и всех менеджеров, выполнение существующих планов и расход работающего DeepSeek. Личный кабинет продаж остаётся доступным отдельно. Ответы владельца 2026-11-01 закрыли брифинг; protected-plan.md подтверждён.

## Решение
R01/R13i: стартовый / перенаправляет admin на /dashboard, остальных на /manager. Обзор есть в навигации администратора desktop/mobile; прямой доступ обычного пользователя к API запрещён сервером. Текущая работа входа, выхода и возврата на запрошенную страницу сохраняется.

R02/R03: сумма и число всех неотменённых продаж manager_sales, включая администраторов, неактивных и архивных сотрудников. Список всех действующих менеджеров даже с нулём, исторические сотрудники также видны и помечены. Сумма строк согласована с итогом. Денежные значения целые копейки; не переопределять продажи как оплату/прибыль/счета. Отменённые исключены, source manual/onec учитываются одинаково.

R04/R11: /manager остаётся полноценным прежним кабинетом, для администратора доступен отдельным действием «Мои продажи» и через меню. В нём сохраняются выбор менеджера, ручной ввод/правка продаж и существующие условия. Не создавать заново импорт из файла: в найденном коде ручной сценарий — ввод продажи. Никакие имеющиеся импорты/Excel/документы не удаляются.

R06–R09: календарные Неделя (пн–вс), Месяц, Квартал, Год. Текущая дата по Москве. Переключение типа, предыдущий/следующий период и возврат к текущему. По умолчанию месяц. Для недели/месяца/квартала ежедневные точки, года помесячные; нулевые точки заполнены, суммы графика сходятся с итогом. Будущие даты без продаж не выдаются за прогноз. Лимит запроса — один выбранный период, строгая дата 1900–2199, без произвольных SQL/без неограниченных диапазонов.

R05: существующие месячные условия manager_periods — единственный источник плана. В кабинете terms отсутствует → «Условия не заданы», plan=0 → «Без плана», plan>0 → продажи месяца / plan ×100, число может превышать 100%, полоса ограничена 100%. Точно сохранить эту семантику. Чтобы не выдумывать недельные/квартальные планы и пропорциональное распределение, отдельный блок «Планы менеджеров — <месяц опорной даты>» всегда показывает месячный факт, план и процент по тем же данным, что кабинет. Для месячного графика этот месяц совпадает с графиком; для остальных явно подписан отдельно. Общий процент не обязателен: не выдавать неполную сумму планов за план всей компании. Все менеджеры остаются видны, план можно посмотреть и задать в прежнем кабинете; новых бизнес-правил начислений нет.

R10: только подготовка OData. Дашборд агрегирует единый журнал, включая уже предусмотренный source=onec, без привязки к ручному вводу. Документировать будущий read-only adapter: идентичность документов/external_id, сопоставление менеджеров, повторная загрузка/исправления/отмены до подключения. Не обращаться к 1С, не вводить ложную кнопку «Синхронизировать», не заявлять что синхронизация включена. Краткая подпись источника: ручной учёт; подключение 1С подготовлено/пока не подключено, различать факт данных с source=onec от активного обмена.

R12: DeepSeek уже рабочий deepseek-flash, секрет настроен. Добавить измерение только числового расхода. В отдельном блоке число попыток запросов, токены входа/выхода/всего (из usage, не оценки), ошибки/неизвестный расход и график по выбранному периоду; текущий баланс отдельно, в валюте провайдера, с временем обновления. Без денежной оценки расхода, собственного бюджета, выдуманного процента квоты или исторического backfill. История до начала учёта отсутствует и обозначена; неизвестное не равно нулю. Запрос баланса не запускает генерацию и не учитывается как OCR-запрос. Токены учесть и если модель вернула невалидный результат с валидным usage. Сохранять по одной записи за фактическую попытку, без новых ретраев. Покрыть Документы, расценку и существующие мобильные пути.

## Состояния и границы
- Продажи и DeepSeek загружаются/ошибаются независимо: отказ провайдера не скрывает продажи. Явный повтор без автоматических бесконечных циклов.
- Пустой период: ноль продаж и подсказка о периоде/ручном вводе. Нет истории usage: объяснение, не фиктивный график. Нулевой подтверждённый баланс отличается от недоступного.
- При смене периода/аккаунта поздние ответы не подменяют новое состояние; не сохранять admin-данные в localStorage или публичный кэш.
- Адаптивный экран в существующем стиле, клавиатурные управления/focus, понятные подписи графиков и доступные значения. Мобильная ширина около 390px и один desktop — достаточно целевой визуальной проверки.
- Прямые вызовы API обычным/анонимным/деактивированным пользователем не возвращают корпоративную аналитику/баланс. Секреты, документы, prompts, filenames и клиентские IDs в метриках отсутствуют.

## Решения по реализации
Существующий Next/React/Recharts и FastAPI/SQLite без новых зависимостей. Новые admin-only read endpoints, additive telemetry migration; старые API, таблицы и результат OCR остаются совместимыми. Явная инъекция telemetry sink во все extractor paths, сбой метрик не прерывает распознавание, UI сообщает неполноту. Баланс — фиксированный HTTPS origin, TLS, bounded timeout/response, без redirects/env proxy; краткий server cache. Границы в interfaces.md, визуальное решение в design.md, источники провайдера в provider-evidence.md.

## Приёмка и выпуск
Один целостный таск, ориентир около 3 тысяч изменённых строк с тестами. Значимые интеграционные проверки на временной БД, frontend проверки/короткий E2E, одно независимое ревью, независимая приёмка по брифу из чистой копии. Не считать mocks live DeepSeek. После зелёных обязательных проверок commit/PR/merge и выпуск в существующий контур авторизованы. Перед выпуском проверить actual runtime/триггеры/backup/restore/rollback и exact main SHA; не восстанавливать старые данные ради code rollback.

## Вне рамок
Реальный обмен продажами с 1С по решению владельца, новый план компании, расчёт зарплат, бюджет DeepSeek, старые телефонные проверки, изменение действующего провайдера/ключа, возврат к Codex. Не удалён ни один пункт исходного запроса.

## Открытые места
Нет решений владельца, блокирующих реализацию. Техническая невозможность восстановить прежнюю usage-историю честно обозначена в UI.
