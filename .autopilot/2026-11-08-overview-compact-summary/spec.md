# Спецификация: Сводка рядом

## Задача
Общий обзор занимает слишком много места панелью кнопок и большим графиком. Реализовать именно первый показанный макет с живыми данными и рабочим раскрытием графика.

## Решение
Один существующий /dashboard. Сохраняются branding и глобальная AppShell/navigation, которые не нужно переделывать на остальных страницах. Макет — reference-selected.png, без рамки презентации и названия концепта. Мобильный макет показывает компактный стек, desktop — график слева около60%, менеджеров справа около40%. Не копировать демонстрационные деньги/имена.

## Визуальная цель
Жёлтый #ffc400, navy #07162e, существующий Segoe UI/Arial, светлый фон, умеренные скругления/границы. Внутри dashboard нет отдельной пустой header-строки. «Мои продажи» встроены в toolbar (на телефоне допустима понятная icon-ссылка с прежним доступным именем), не вынесены в отдельный пустой ряд. Не возвращаются удалённые h1/подпись. Не добавлять декоративные KPI, новые разделы, маршруты или зависимости.

## Управление
Первая компактная строка: переход предыдущий/следующий период, читаемая текущая дата/месяц согласно выбранному периоду; загрузка выписки, история, личный кабинет. На телефоне подписи допустимо сокращать визуально, но сохранять aria-label «Загрузить выписку», «История выписок», «Мои продажи →» и рабочие44px цели касания. Вторая компактная строка — Неделя/Месяц/Квартал/Год с активным выбором, календарь и «Сегодня»; диапазон и дата сегодня — тихая строка без крупной панели.
Календарь — доступный выбор календарной даты отчёта в пределах1900–2199, без UTC-сдвигов; допустим native date input в небольшом dialog по icon-кнопке. Не менять API-семантику week/month/quarter/year. Переключение обновляет данные; запоздавший ответ другого периода не выдаётся за текущий.

## Сводка
Одна общая белая панель «Продажи компании», реальная полная сумма с НДС, количество оплат. Внутри — компактный «По дням» (около150–180px на телефоне и200–240px на desktop) и менеджеры. На390×844 график и первые3реальные строки видны вместе выше нижней навигации; на360px нет горизонтального overflow. При большем числе менеджеров все строки остаются доступными через ограниченный scroll-список; их нельзя отбрасывать/подменять.
Manager name, actual selected-period salesTotal/count and share come from API. Сохранить monthlyPlans.month/status/progress и информацию архив/неактивен в компактной дополнительной строке. Monthly plans не смешиваются с выбранным period salesTotal. Ссылка прежняя /manager?managerId=<manager_accounts.id>&month=<monthlyPlans.month>. Нет предположения id=userId.
Строка «Не распределено» сохранена. Информация об источниках/1С и исходные «Данные графика» остаются доступными, но могут быть в details, чтобы не раздувать первый экран. Текущие DeepSeek/balance секции сохраняют поведение ниже сводки; общие графики также можно уменьшить без потери значений/доступной таблицы.

## Подробный график
Нажатие самого графика или очевидной expand-кнопки открывает полноценный фиксированный dialog на весь доступный viewport (портал выше AppShell/bottom nav), увеличенный plot, тот же выбранный period/диапазон/сумма, доступные значения. На inline preview нет постоянно перекрывающего график tooltip. Dialog использует существующие Base UI primitives: focus trap, Escape/видимая закрывающая кнопка, возврат фокуса к открывшему контролу, блокировка фонового scroll. После закрытия выбранный period/date и данные не теряются. График не дублирует продажи и не выполняет mutation.

## Состояния и границы
Загрузка, отсутствие продаж/менеджеров, ошибки и retry сохранены. Нулевые суммы — нули, не «нет данных»; неизвестные balance values сохраняются неизвестными. Longnames/large money и scroll-перечень не ломают layout. Обычный пользователь не запрашивает admin datasets и не видит импорт; API/backend ACL прежние.
Backend, API contracts, schema/migrations, money/commission formulas, CRM attribution, bank parsing/dedup/privatefiles и другие разделы не меняются. Рабочие данные не используются для тестовых записей. Весь acceptance — синтетические API/SQLite/storage через существующие изолированные npm scripts.

## Проверки
Affected React integration — переключение period/date, реальный total/менеджеры, modal open/close + keyboard, retry/empty/user role. Короткий real-browser flow desktop и390×844/360 через предусмотренный isolated launcher: контролы, отсутствие пустой header-строки/overflow, chart+manager visibility, expand/close/Escape/focus/date preservation, manager link, upload+history. Screenshot comparison с выбранным макетом; только синтетические данные. Существующий frontend checkset (auth/settings/lint:ci/tsc/build и обязательный CI) до merge. Один fresh whole-change review, narrow correction if warranted; независимая blind acceptance может быть частью того же final review согласно owner policy. G2 — отдельно сверяет только brief и spec.

## Вне рамок и открытые места
После зелёных проверок — PR, merge и ранее разрешённый frontend-only deploy в согласованный VPS91.227.68.176 по действующему runbook, с проверенным backup/rollback и public smoke. Backend/data/1С не меняются.
Новых бизнес-возможностей/обязательных placeholders нет. Глобальная AppShell и sidebar сохраняются, хотя презентационный desktop-mock не содержит sidebar; это намеренная граница согласованного существующего продукта. Никаких новых расчетов или fake-данных в production.
