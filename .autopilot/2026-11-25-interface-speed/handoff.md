# Быстродействие интерфейса

Проверенный продуктовый коммит `61832af`. Тема «Стекло» применяется по умолчанию с релиза `d1c5696`.

- При быстром возврате в «Обзор» число запросов за данными сократилось с пяти до нуля. Повторная анимация SVG составила ноль изменений вместо примерно 0,4 секунды. Кэш текущей вкладки свеж 30 секунд, снимок доступен до пяти минут с фоновой актуализацией при возврате.
- В «Моих продажах» повторный вход использует снимок той же сессии, периода и просматриваемого сотрудника. Выход, смена сессии и отказ сервера исключают применение прежних данных. Записи инициируют актуализацию.
- Переходы в настройки пользователей и 1С выполняются через приложение. CRM переиспользует метаданные вкладок в пределах выбранного владельца. Запросы прав, свежие списки CRM и согласованный порядок синхронизации сохранены.
- В симуляции задержки 120 мс и замедления процессора 4× первый переход «Обзор → Остатки» занял 456 мс против исходных 551 мс. В том же прогоне повторный переход занял 284 мс против 187 мс в исходном. Это отдельные замеры на изолированных данных.

## Проверки

- `npm run test:auth` — 275.
- `npm run test:settings` — 104.
- `npm run lint:ci`, `npx tsc --noEmit --incremental false`, production-сборка — успешно.
- Матрица изолированного браузера — 11 пройденных сценариев, 4 ожидаемых пропуска по профилям. Три профиля прошли все 14 пунктов меню администратора и 12 доступных пунктов сотрудника. Точечная перепроверка финального исправления — два сценария Chromium прошли.

Реальные телефоны, рабочая база и обмен с 1С в замерах не участвовали. Деплой является отдельной операцией.

Полный браузерный прогон выявил два регресса прежних сценариев. Редактор продажи теперь явно закрывается после успешного сохранения, классическая диаграмма снова рендерится без анимации. Изменения проверяются существующими браузерными сценариями.
