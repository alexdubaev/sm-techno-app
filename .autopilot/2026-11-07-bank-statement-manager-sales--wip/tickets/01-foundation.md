## Что должно заработать
Безопасная миграция сохраняет старые продажи, добавляет банковский источник и раздельные сущности выписки. Администратор может исторически закрепить клиента за активным manager_accounts.id. Импорт получает общий внутренний механизм записи продаж в общей транзакции.

## Из брифа, дословно
> «На одну дату у клиента может быть только один менеджер по продажам»
> «Не делать обходной INSERT, игнорирующий существующие правила»

## Разделы спецификации
Все правила схемы/закреплений/существующих продаж; interfaces.md секции 1–3.

## Критерии приёмки
- [ ] Чистая, заполненная и повторная миграция, сохранение ID/всех полей/индексов/FK/снимков.
- [ ] В БД исключены пересечения интервалов; исправление истории требует причину; manager_accounts.id != users.id протестировано.
- [ ] Аккаунт связан с активным users; архивный клиент блокируется; смена закрепления не меняет продажи.
- [ ] Общий helper на переданном conn сохраняет месячные проверки, аудит, versions, limits и формулы; HTTP не принимает доверенные банковские поля.
- [ ] Готовая схема для persisted uploads/sources/operations/decisions/audit/links/idempotency и account settings, без дублирования manager_sales.
- [ ] Новые интеграционные тесты сначала RED, затем GREEN + затронутые manager migration/repository/adversarial.
