## Модули и владение
1. bank_schema.py: миграция web registry; import account settings с organization_id из organizations; uploads, source rows, immutable operations, versioned decisions + audit, sale links, commit idempotency, dated assignments/history. Имена/поля фактической реализации foundation дописываются ниже до downstream. manager_sales расширяется source bank_statement и CRM/operation связями с сохранением ID/полей/индексов. Таблицы ledger не дублируются. Непересечение назначений обеспечено SQLite trigger и immediate транзакцией.
2. bank_assignment_repository.py: admin account settings, exclusive assignment intervals [start,end), mandatory start/reason, active account joined users via user_id. Assignment at date; backdate modifies only interval containing date or inserts gap up to next interval. No historical sale movement. Returns pending operation count/range/gross amount after assignment. Existing CRM permissions untouched.
3. manager_repository.py: extract current transactional mutation into internal helper accepting existing sqlite transaction. Public API cannot set trusted bank source/IDs. Bank commit calls same helper for sale constraints, audit and period versions. Imported sale may be cancelled normally; bank link persists; editing bank financial identity blocked. Existing API compatible.
4. bank_parser.py: pure parse_statement(raw: bytes) -> JSON-serializable dict {parserVersion,metadata,rows,errors,reconciliation}. Metadata ownerName, ownerInn, account, bik, periodStart, periodEnd, currency, debitTotal, creditTotal, openingBalance, closingBalance. Row {sheet,row,raw,normalized,errors,warnings}; normalized {date,documentNumber,debit,credit,payerName,inn,kpp,account,bik,bankName,purpose,debtorCode,documentType,invoiceReferences,invoiceNumber,invoiceDate,direction}. Money ints or null on invalid; raw exact serializable strings and cell types/formulas preserved. Fatal invalid structure returns understandable ValueError, valid structure with row/totals errors can persist blocked preview. Formula never trusted; preflight ZIP bounded, XML safe, no links/macros, date 1900–2199. Metadata unknown balance null. Invoice ambiguity warnings nonblocking. Limits constants exported. No CRM/storage/network access.
5. bank_repository.py: all persisted preview/manual decisions/matching/dedupe/commit. Strict cross-upload operation identity excludes filename/sheet/row/period, includes organization/account/currency/direction/date/document/payer details/amount/purpose/additional source signs. Repeated indistinguishable rows in one file all retained and blocked group; no silent disappearance. Changed purpose/incomplete key probable duplicate requires explicit admin resolution. Stored source rows every occurrence linked to operation. Manual/onec matches require reason/new or one-to-one link, validate same amount/client/manager; legacy no CRM requires documented exact client match, no heuristic rewrite. Re-evaluation on refresh and after assignment returns version/fingerprint incorporating assignment/client/account/terms/period and duplicate candidates. Commit rechecks fingerprint and decision versions under BEGIN IMMEDIATE. Idempotency content hash persisted same transaction; identical retry returns same response, different content 409. Selected set atomic. calculate() gives before/after sale/commission/income delta. No sales created by preview.
6. bank_api.py: create_bank_router(get_current_user,get_db,get_storage_root), mounted once in stock_sync_api. Namespace /api/bank-statements. No-store, generic safe errors, bounded UploadFile and admin before parsing. GET /accounts => organizations plus confirmed accounts; POST /accounts confirms organization/account/bik (reason). GET /uploads, POST /uploads multipart accountId/file, GET /uploads/{id}, POST /uploads/{id}/refresh, GET /uploads/{id}/file admin only. PATCH /operations/{id} version/clientId/classification/reason/duplicateAction/linkSaleId/invoice corrections; POST /preview {items:[{operationId,version,fingerprint}]} => effects, no ledger write; POST /commit same items + idempotencyKey => sale count/link count/effects. GET /clients/{id} => assignment/history admin only, current assignment label + scoped own posted payments for permitted manager. PUT /clients/{id}/assignment {managerId|null,startDate,reason,version} admin. GET /clients/search?query admin-only client picker (or existing CRM safe search). All direct ID access authorized; nonadmin no raw purpose/payer account/other salary/full file.
7. Frontend bank-types.ts mirrors actual API; api.ts authenticated methods; bank-import.tsx reusable admin modal/page in existing ManagerWorkspace, global across selected manager. Compact mobile cards, details disclosure, all statuses, persistent history/account config/manual decisions/refresh/review totals/idempotent confirm/download. CRM sales panel reused desktop/mobile; manager account picker IDs, required date/reason/history/pending summary, scoped receipts. Existing manager sales source label bank_statement. Preserve cache invalidation after import and assignment using existing callbacks/state refresh; no unrelated design change.
