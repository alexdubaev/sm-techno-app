# DeepSeek: основа подключения подготовлена

Документы и загрузка артикулов в Остатках используют единый выбираемый обработчик. DeepSeek принимает подготовленный текст и встроенные изображения, возвращает локально проверяемые данные; прежние ручная проверка менеджером, создание Word и связь с CRM/1С сохраняются. Переключение явное, автоматического перехода на другой сервис нет. По умолчанию остаётся codex.

Для будущего включения в защищённом окружении backend нужны DOCUMENT_ASSISTANT_PROVIDER=deepseek и DEEPSEEK_API_KEY; модель по умолчанию deepseek-flash. Ключ намеренно пуст, в чат/репозиторий его не передавать. Инструкция docs/deepseek-document-provider.md. После настройки ключа требуется реальный canary в отдельном синтетическом экземпляре, затем отдельный серверный выпуск с новым проверенным backup. Точность распознавания сейчас NOT RUN.

Проверки: исходный extraction16PASS; affected document+stock118PASS до последнего deadline изменения; финальный narrow closure18PASS после исправления send/header/body timeout. Независимый clean clone acceptance4PASS и один security review; один подтверждённый finding исправлен, повторного whole review нет. Полные факты и ограничения в checks.md. Системный DNS подчиняется resolver ОС и не прерывается таймером активного HTTP соединения.

Не вошли по текущему поручению: реальный ключ/платные запросы/проверка качества DeepSeek и переключение VPS. Предыдущая версия сервера, закрытые backups/images и runtime preparation PR13 сохранены. Это завершение подготовки адаптера, не завершённый deploy.
