# План, требующий подтверждения: Android/mobile intake

1. В существующих Остатках три способа: вставить текст/ячейки, выбрать фото/скриншот, выбрать файл/desktopdrop. Показать выбранный источник; распознавание по кнопке, затем проверка строк и оба прежних Excel. Без клиента/КП/сохранённой расценки/резервов.
2. Установленное ChromePWA появляется в Android «Поделиться». Полученный File/текст приходит в тот же /stock. Пустая передача/тольконазвание/ссылка/ошибкабраузера не отправляются модели: понятный recovery к общим кнопкам.
3. Новый browserworker ограничен служебным /stock-share/; не перехватывает обычные страницы/API, не кэширует данные и не меняет backend/sessionformat. Две навигационные точки приёма/проверкиверсии, не OCR API. Login/account lifecycle observer только связывает входящую передачу с текущей проверенной сессией.
4. Payload держится в памяти до120с/одноразовогополучения/отмены; не записывается в постоянное хранилище/очередь. Только служебная привязка actor+hashсессии может переживать worker restart. Имена/содержимое/токены в неё не входят. На logout/userchange/новыйlogin/несовпадение передача отбрасывается, пользователь входит и пересылает заново. Другой аккаунт её не получает.
5. Code-onlyrollback сохраняет текущуюБД/подключения, новыйworker обнаруживает отсутствиеversionmarker и отключает только собственныйscope. Проверки realBrowserSW+ownership/bounds/TTL/cancel/2Excel, freshreview+boundedfix, физический Androidownercheck. Затем PR/main; отдельно согласованный exactSHAdeploy со freshverifiedbackup/rollback.

Причина согласования: добавляются новый HTTP-вход OSshare и привязка приватного входящего файла к авторизованной сессии. AGENTS.md запрещает изменения API-контрактов без отдельного подтверждённого плана; ownerpolicy сохраняет FULL gates для auth/session/private-media/recovery. Решения подготовлены и проверяются независимым читателем до вопроса. Никакого нового внешнего сервиса/платежа/аккаунта/ключа.

Техническое условие Androidinstallability: подготовить192px PNG обычным программным масштабированием существующей512px иконки с жёлтым логотипом; исходник не менять и не перерисовывать, новый сервис генерации изображений не нужен. В существующем favicon.svg другой старый знак — его не использовать. РазмерPNG проверить фактически.
