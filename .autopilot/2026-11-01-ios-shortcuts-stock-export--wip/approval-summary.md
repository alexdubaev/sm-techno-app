# Что предлагается подтвердить перед реализацией

1. **Два Excel в Остатках.** Обычный файл сохраняется. Второй использует наш действующий шаблон КП: только товары с положительным остатком и ценой, все подходящие склады, складская цена и фактическое количество. Без цены строка не включается, появляется предупреждение. Без подходящих товаров пустой файл не создаётся. Клиент/номерКП не выбираются, КП/подборка/история в базе не создаются.

2. **Своё подключение каждого телефона.** В Остатках появится «Команды iPhone»: создать подключение, один раз скопировать персональный код, посмотреть свои подключения и отключить любое. Код даёт только расценку/Excel, не доступ к остальному приложению. Пароль/вход в приложение и ключ DeepSeek не передаются в команду.

3. **Один общий сценарий для сотрудников.** При первом добавлении сотрудник вставляет свой код. Далее: файл в мессенджере → «Поделиться» → команда → просмотр распознанных артикулов → выбор обычного Excel или файла по шаблону КП → Excel открывается на телефоне. Отмена не создаёт никаких документов. Распространяется общий сценарий без личного кода. Реальную установку/публикацию команды в iCloud нужно один раз проверить на iPhone; выдуманной готовой ссылки не будет.

4. **Защищённые изменения.** Добавятся отдельный реестр подключений в базе и новые API только для мобильной расценки. Текущая авторизация сохраняется. При смене пароля, отключении/изменении роли сотрудника или удалении аккаунта его подключения отзываются; обычный выход из одного браузера не отключает телефоны. В базе только хеш кода, не сам код. Сроки как у текущих сессий:180дней бездействия/неболее365дней. Есть ограничения на частоту запросов.

5. **Восстановление и выпуск.** После настоящего восстановления базы из резервной копии телефоны потребуется подключить заново. Обычные обновления и откат только кода подключения сохраняют. Сначала изолированные проверки, проверка XLSX и независимое ревью безопасности; выпуск на существующий сервер отдельным шагом по проверенному mainSHA со свежей резервной копией и сохранённым откатом. Рабочая1С,DNS/Caddy и чужие данные/ресурсы не меняются.

Технический контракт и точные границы: protected-plan.md. Две последовательные задачи реализации, существующий интерфейс и прежние процессы сохраняются.

Почему требуется подтверждение: AGENTS.md прямо предписывает «Не менять API-контракты, схему данных, миграции и интеграцию с 1С без отдельного подтвержденного плана». Здесь затрагиваются новые API, реестр устройств и безопасное восстановление;1С не меняется. Это одно согласование конкретного плана, не просьба повторить разрешение на всю задачу.
