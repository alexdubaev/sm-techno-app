# Спецификация: удобный интерфейс Документов и главного меню

## Задача
Менеджер создаёт договор или спецификацию из файла реквизитов или счёта. Сейчас это много лишних нажатий, все кнопки одинаково серые, на нажатие нет видимой реакции, непонятно, на каком шаге он находится и что делать дальше. В главном меню нажатая группа не подсвечивается, пока не откроешь подраздел, а подразделы появляются рывком.

## Решение
Раздел «Документы» ведёт менеджера по шагам: выбрал режим → бросил файл → распознавание стартует само и видно, что идёт работа → проверил поля → подтвердил клиента → получил документ и сразу может его скачать. Кнопки в фирменном стиле: главное действие жёлтое, второстепенные — светлые с рамкой; каждая кнопка отзывается на наведение, нажатие и показывает загрузку. Меню подсвечивает нажатую группу сразу и плавно раскрывает её подразделы.

Серверная часть, API, права и порядок работы с 1С не меняются (R01). Все существующие сценарии и данные сохраняются (R09i).

## Решения по реализации
- Только frontend (`sm-techno-web`), без новых зависимостей. API-функции из `lib/api.ts` и `lib/document-workflows-api.ts` вызываются те же и с теми же аргументами.
- Стили кнопок — расширение существующего `.app-action-button` в `globals.css` модификатором второстепенного стиля и состоянием `aria-busy`; почему: проект уже использует этот класс, а shadcn `Button` страницами не используется.
- Автозапуск — новый необязательный prop панели распознавания, включаемый только в Документах; почему: `/clients` использует ту же панель и должна остаться прежней.
- Скачивание после генерации — существующий `downloadDocumentFile` по id созданного документа (из ответа/сводки клиента).
- Плавное раскрытие меню — CSS (`grid-template-rows 0fr→1fr` + opacity), контейнер всегда в DOM с `inert` в свёрнутом виде; почему: без библиотек и без измерения высоты.
- Обновлённые тесты меняют только селекторы/тексты, затронутые новым UI; проверки сценариев не ослабляются.
