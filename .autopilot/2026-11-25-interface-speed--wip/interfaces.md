# Границы, решённые в спецификации

- 01 — продажи. Область: admin-dashboard, manager, новый клиентский хук или узкое расширение lib/api.ts и относящиеся тесты. Использовать действующий механизм invalidation и разделение по сессии, без новых зависимостей, API путей или localStorage для показателей. Ответы после инвалидирования не записывать. Источники данных и бизнес-вычисления остаются существующими. Снимок не используется при 401/403 или при неподтверждённой сессии.
- 02 — интерфейс. Область: app-shell, app/glassy.css, settings link, stock-page и work-with-invoice. Свежесть каталога управляется текущими механизмами. Первичная оптимизация готовит только действительно нужный маршрут и оставляет раннюю обратную связь. UI и бизнес-права сохраняются.
- 03 — CRM. Область: CRM workspaces и связанные вспомогательные файлы/тесты. Согласованные правила синхронизации, ACL и явные действия. Сократить вызовы одного запроса в одной операции или запросы той же лёгкой метаинформации в рамках действующего жизненного цикла.
- Проверки из sm-techno-web: npm run test:auth, npm run test:settings, npm run lint:ci, npx tsc --noEmit --incremental false, npm run build, npm run test:auth:e2e. E2E только штатным npm-скриптом с изолированными данными. Для локального прогона используется существующий тестовый Python.
