# Источник кода и контуры публикации

## Правило разработки

## Backend proxy и тесты

Актуальный Next.js same-origin proxy читает серверную `BACKEND_API_BASE_URL`. Не коммитить production-значения и секреты. Внешние runtime settings управляются только в согласованном контуре, изменение требует отдельной публикации и проверки.

Playwright запускается только через `npm run test:auth:e2e`: allowlist исключает рабочие URL, БД, storage и настройки обмена. Конфигурация тестового Next.js задаёт `BACKEND_API_BASE_URL=http://127.0.0.1:18000`, frontend использует 127.0.0.1:13000; backend получает временные данные и синтетический ключ. Vite/Worker mapping не является текущей конфигурацией Next.js.

После отдельно разрешённого deployment проверить публичный same-origin proxy:

```powershell
cd sm-techno-web
npm run test:deployment:auth-smoke -- https://<согласованный-домен>
```

Это read-only health-проверка; успешный локальный build не доказывает состояние работающего сайта. Не менять DNS/Caddy/контейнеры/тома и не выполнять записи в рабочую 1С в рамках Git-уборки.
