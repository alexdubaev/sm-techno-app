# Источник кода и контуры публикации

## Правило разработки

GitHub main — единственная постоянная линия разработки. Backend и sm-techno-web проходят PR и проверки вместе. Выпуск отдельно по утверждённому SHA из main; merge не является командой на деплой.

## Текущее решение по контурам

По указанию пользователя от 2026-10-06 Sites и Vercel не используются и исключены из публикации. Vercel Git deployments отключены через `git.deploymentEnabled: false` в корневом и frontend `vercel.json`. Их прежний статус и зеркала не являются условиями merge или выпуска.

Оставшаяся цель публикации (серверный или локальный контур), доступ к ней и фактический runtime SHA пока не подтверждены. Проверка 2026-10-06: документированный VPS `91.227.68.176` отклонил вход с доступными SSH-ключами; нельзя считать его доступной или активной целью без проверки.

## Исторический аудит 2026-10-01 (заменён решением 2026-10-06)

- В GitHub deployments есть записи Production/Preview от vercel[bot]. Отсутствие deploy-job в Actions не означает отсутствия автопубликации.
- Для подготовки `codex/repository-cleanup-2026-10-01` в root и frontend vercel.json был запрещён Git deployment именно этой ветки. Это историческое состояние заменено текущим решением выше.
- На тот момент Sites считался активным; найденная версия и source SHA — исторические сведения, заменённые решением от 2026-10-06.
- VPS: фактический серверный checkout/SHA и зависимость скриптов от `codex/vps-self-hosting` не подтверждены. Ветку сохранять до проверки. Описание в старом runbook не является свидетельством текущего состояния сервера.

Целевой порядок: получить согласованный SHA из main, подтвердить доступ и runtime SHA оставшейся цели, выполнить отдельно разрешённый backup и deployment, подтвердить health и затронутые сценарии.

## Backend proxy и тесты

Актуальный Next.js same-origin proxy читает серверную `BACKEND_API_BASE_URL`. Не коммитить production-значения и секреты. Внешние runtime settings управляются только в согласованном контуре, изменение требует отдельной публикации и проверки.

Playwright запускается только через `npm run test:auth:e2e`: allowlist исключает рабочие URL, БД, storage и настройки обмена. Конфигурация тестового Next.js задаёт `BACKEND_API_BASE_URL=http://127.0.0.1:18000`, frontend использует 127.0.0.1:13000; backend получает временные данные и синтетический ключ. Vite/Worker mapping не является текущей конфигурацией Next.js.

После отдельно разрешённого deployment проверить публичный same-origin proxy:

```powershell
cd sm-techno-web
npm run test:deployment:auth-smoke -- https://<согласованный-домен>
```

Это read-only health-проверка; успешный локальный build не доказывает состояние работающего сайта. Не менять DNS/Caddy/контейнеры/тома и не выполнять записи в рабочую 1С в рамках Git-уборки.
