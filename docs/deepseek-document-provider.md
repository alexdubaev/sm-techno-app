# DeepSeek для распознавания документов

По умолчанию используется существующий провайдер `codex`. Для выбора DeepSeek задайте в серверном окружении:

```dotenv
DOCUMENT_ASSISTANT_PROVIDER=deepseek
DOCUMENT_ASSISTANT_DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_API_KEY=
```

Ключ предоставляется отдельно и хранится только на сервере; не отправляйте его в чат и не добавляйте в Git или frontend. Для возврата к прежнему провайдеру установите `DOCUMENT_ASSISTANT_PROVIDER=codex`. Перезапустите backend по принятой процедуре после согласованного изменения окружения.

Документы передаются DeepSeek как извлечённый текст и встроенные изображения; переключение на другого провайдера при ошибке не выполняется. Результат проверяется локально, а его данные требуют существующего подтверждения. Используется только `https://api.deepseek.com/chat/completions` с проверкой TLS; прокси окружения и перенаправления не используются. Реальный запрос требует отдельно предоставленного ключа; точность модели должна быть проверена на согласованных данных.

Срок задаётся существующей переменной `DOCUMENT_ASSISTANT_TIMEOUT_SECONDS` и ограничивает отправку, получение заголовков и тела активного HTTP/TLS-соединения. Системное DNS-разрешение до получения сокета подчиняется настройкам ОС и этим таймером не прерывается.

В расценке артикулов таблицы XLSX/XLS/CSV/TSV читаются обычным кодом без DeepSeek, Codex и ключей провайдеров — как в приложении, так и через «Команды». Требуется один однозначный столбец артикулов («Артикул», «Арт №», «КАТ №», SKU и другие поддерживаемые заголовки); количество необязательно. Порядок, повторные строки, номера строк и нулевые количества сохраняются. Максимум — 1000 позиций, 10000 строк и 200 столбцов; прежние ограничения загрузки и ZIP остаются. Формулы в артикулах и количестве XLSX требуют замены на проверенные значения; формулы не исполняются. Неизвестная структура даёт ошибку, без передачи файла в AI. У XLS используются сохранённые значения ячеек; вычисление формул не запускается. Ведущие нули текста и явно заданного Excel-формата сохраняются, испорченные длинные числовые идентификаторы не восстанавливаются догадкой.

Для остальных материалов при извлечении артикулов (`articles`) запрос явно отключает `thinking`, который [включён у DeepSeek по умолчанию](https://api-docs.deepseek.com/guides/thinking_mode/). Для счетов, реквизитов и договоров режим не переопределяется. Проверка JSON, количества строк, артикулов и числовых значений остаётся обязательной. Нулевое количество запроса допустимо для расценки; количество позиции счёта по-прежнему должно быть положительным.

Потребитель расценки списка использует общий бюджет подготовки и ожидания DeepSeek 300 секунд по умолчанию, передавая провайдеру оставшееся после подготовки время. Явное значение `DOCUMENT_ASSISTANT_TIMEOUT_SECONDS` сохраняет приоритет и прежний диапазон 15–300 секунд. Остальные документы сохраняют прежний срок по умолчанию 120 секунд. Ключ, модель и production-окружение эта правка не изменяет.
`nТабличный формат требует явного заголовка. Поддерживаемые названия столбцов зарезервированы при выборе шапки: например, одноколоночное SKU / 123 / 456 означает заголовок SKU и две позиции. Списки без заголовков следует вставлять текстом или дополнить заголовком «Артикул». После выбора шапки каждую непустую строку читаем как данные; артикул SKU / КАТ / PN в данных не отбрасывается.
