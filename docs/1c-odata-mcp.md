# Локальный MCP-доступ к 1С

В проект добавлен локальный сервер `1c-odata-mcp` версии 0.8.0. Codex запускает его по настройке `.codex/config.toml`; каталог `tools/1c-odata-mcp` содержит отдельную npm-зависимость и launcher, не затрагивающие frontend.

## Настройка

1. Используйте Node.js 22 LTS или новее (Node.js 20.12+ поддерживает `util.parseEnv`, но рекомендована поддерживаемая LTS).
2. Скопируйте `.env.onec-mcp.example` в `.env.onec-mcp` в корне проекта и укажите адрес одной базы OData, имя пользователя и пароль. Файл игнорируется Git.
3. В корне проекта выполните `npm --prefix tools/1c-odata-mcp ci --ignore-scripts`.
4. Перезапустите Codex, чтобы он перечитал `.codex/config.toml`.

Launcher читает только корневой `.env.onec-mcp` и передаёт серверу только адрес и учётные данные плюс фиксированные безопасные лимиты. Он принудительно устанавливает `READ_ONLY=true`, `ODATA_WRITABLE=false` и не передаёт `NODE_OPTIONS`, `ODATA_DB_*` и прочее окружение процесса. Конфигурация Codex открывает только инструменты `read.*`. Запись в 1С недоступна.

Для локального тестового harness допустим синтаксис `node tools/1c-odata-mcp/run.mjs --env-file <path>`; этот параметр предназначен только для проверки и не меняет конфигурацию Codex.

Проверка установки и защиты выполняется без живой 1С:

```powershell
npm --prefix tools/1c-odata-mcp run check
```

Скрипт поднимает синтетический OData endpoint и проверяет MCP-инициализацию, список инструментов, health-check, изоляцию враждебных переменных окружения и блокировку попытки записи без HTTP-мутации.

Лимиты намеренно ограничены: обычные выборки — до 500 строк, аналитические — до 10 000 строк. При больших периодах запрос может завершиться ограничением; такие результаты нельзя считать полной картиной без проверки объёма данных. Запускайте Codex с корнем этого проекта как рабочей папкой: путь к launcher в `.codex/config.toml` задан относительно корня репозитория.

Поиск `read.counterparty.find_counterparty` в upstream ориентируется на программное наименование (`Description`/`name`) и может не найти запись по полному наименованию. Перед подготовкой клиентских документов или снапшотов используйте `read.counterparty.get_counterparty` и поле `fullName` (`НаименованиеПолное`); результат поиска по `Description` не подтверждает совпадение с документным наименованием. Подключение не проверяет соответствие аналитических маппингов upstream конфигурации вашей базы: health-check подтверждает только доступность OData и чтение метаданных.
