# Глобальный архив клиентов 1С в CRM — дизайн

## Цель и границы

Администратор получает локальный для CRM архив клиентов 1С в системной вкладке «Клиенты 1С». Архивация скрывает клиента из активной CRM у всех пользователей, но не меняет данные в 1С и не удаляет локальные данные. Восстановление возвращает тот же объект в активную CRM.

В область входят backend, SQLite-миграция, синхронизация, рабочие списки, поиск, напоминания, Excel import/export, audit и desktop/mobile интерфейс. Не изменяются существующие операции `archive_assignment` и `archive_local_client`, а также семантика `is_inactive` — этот признак продолжает отражать состояние из 1С.

## Данные и синхронизация

Автоматическая миграция `WebDatabase` добавляет в `crm_clients` nullable-поля:

- `crm_archived_at TEXT`;
- `crm_archived_by_user_id INTEGER`;
- `crm_archive_reason TEXT`.

Клиент активен, когда `crm_archived_at IS NULL`. При архивировании устанавливаются текущая UTC-метка, ID администратора и нормализованная необязательная причина; при восстановлении все три значения очищаются. Записи `crm_assignments`, `crm_contacts`, `crm_row_preferences`, `crm_primary_row_preferences`, events, reminders и `crm_audit_actions` не меняются.

Поток загрузки и upsert из 1С не включает эти три столбца в обновляемый набор. Поэтому 1С может обновлять реквизиты архивной записи, но не способен сам восстановить её или стереть метаданные архива.

## Серверный контракт и доступ

Repository получает чётко разделённые методы: archive/restore для linked primary-клиента, admin-only list/archive detail и общие активные выборки. Все запросы, представляющие активную работу, присоединяют условие `crm_clients.crm_archived_at IS NULL` к уже существующему условию `is_inactive = 0`.

API добавляет следующие admin-only endpoints:

- `POST /api/crm/clients/{client_id}/primary-archive` с `{ reason?: string }`;
- `POST /api/crm/clients/{client_id}/primary-restore`;
- отдельную выборку системного списка архива с агрегированным числом активных и архивных primary-клиентов.

Оба mutation-endpoint проверяют авторизацию, `admin`, существование linked primary-клиента и его ожидаемое состояние. Повторная операция возвращает понятный конфликт, а не выполняется молча. Архивирование и восстановление не вызывают 1С. В audit добавляются действия `archive_primary_client` и `restore_primary_client`; отображаются российскими пользовательскими подписями и используют существующую модель reason/actor/timestamp.

Detail архива доступен исключительно admin и сериализует существующие реквизиты, контакты, историю, назначения, владельцев и информацию об архиве. Операции, меняющие активную CRM (перемещение, цвета, порядок, контакты, напоминания), не допускаются для архивной записи; восстановление — единственное основное действие.

## Скрытие из активной работы

Ограничение применяется на сервере, не в клиентском фильтре:

- primary list, личные вкладки, search и `workOwners` не возвращают архив;
- reminder-list и due-reminders исключают записи, чей родитель архивирован; существующие reminders остаются в БД и начинают участвовать снова после восстановления;
- export берёт только активные карточки и контакты их активных родителей;
- Excel import строит снимок архивных совпадений, исключает эти строки из create/update/assign и показывает результат «Клиент находится в архиве — импорт пропущен». Импорт никогда не очищает архивные поля.

Существующие назначения и предпочтения не удаляются, поэтому после восстановления клиент снова появляется во всех прежних рабочих представлениях, с цветом и относительной позицией настолько точно, насколько это позволяет текущая схема порядка.

## Интерфейс

В «Клиенты 1С» только для admin появляется системный переключатель «Активные N | Архив M», не создающий пользовательскую `crm_tab`. Активный режим использует текущие desktop-таблицу и mobile-карточки. Архивный режим получает отдельные desktop-строки и mobile-карточки с компанией, ИНН, городом, датой, `users.full_name` архивировавшего и причиной.

Активная primary-карточка администратора показывает вторичное действие «Архивировать» с подтверждением и необязательной причиной. В mobile это действие находится в «Ещё → Администрирование». Архивная карточка открывается read-only и даёт подтверждённое «Восстановить». Обычный пользователь не получает ни переключатель, ни архивные маршруты, ни административные действия.

После успешной мутации текущий workspace-кэш и активный/архивный списки перезагружаются с backend, чтобы desktop и mobile не показывали устаревшего клиента.

## Ошибки и тестирование

Backend покрывает права, инварианты linked primary-клиента, сохранность связанных записей, audit и отсутствие обращений к 1С. Отдельно проверяются archive → sync → reload, скрытие у нескольких владельцев, reminders, export, import и restore.

Frontend покрывает admin/user visibility, переключатель и счётчики, архивирование, read-only detail, восстановление и обновление состояния в desktop/mobile. Существующие CRM, Python и TypeScript/React проверки запускаются после новых адресных тестов.
