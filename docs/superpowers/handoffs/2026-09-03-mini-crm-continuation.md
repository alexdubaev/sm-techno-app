## 3. Что фактически готово в persistence-слое

Реализовано в `stock_sync_web/database.py` и `stock_sync_web/crm_repository.py`, без второго контура БД, авторизации или OData:

- Идемпотентная миграция существующей `crm_clients`: поля CRM-владельца, города и сайта; исторические карточки и документные идентификаторы сохраняются.
- Таблицы `crm_tabs`, `crm_assignments`, `crm_contacts`, `crm_events`, `crm_reminders`, `crm_row_preferences`, `crm_audit_actions`, `crm_sync_state`, `crm_sync_jobs`.
- Уникальная постоянная вкладка `В работе` на пользователя и ограничение единственного активного назначения «пользователь + компания».
- Локальная карточка создаётся с владельцем; чужой пользователь не может угадать её ID и прочитать/назначить её. Старую локальную карточку без владельца может принять только администратор.
- Личные вкладки с запретом системных имён/изменения постоянной вкладки; удаление пользовательской вкладки атомарно переносит назначения в выбранную вкладку.
- Авторизованные owner/admin-операции вкладок, назначений, личных контактов, событий, напоминаний, настроек строки и аудита. Админский контекст требует явного owner ID; обычный сотрудник не может указать чужой owner ID.
- Перенос между вкладками сохраняет цвет, создаёт событие перемещения и не создаёт клиента в 1С.
- Архивирование/восстановление назначения доступно только администратору, отменяет активные напоминания при архиве и пишет фактического исполнителя и владельца в аудит.

Это фундамент, но не вся реализация требований: в нём ещё нет законченных HTTP-контрактов, UI, Excel, полноценной серверной сортировки по соседям/версиям, палитры с валидацией, связки/очереди 1С, конфликтов и полной модели архивирования локальной карточки.

## 6. Последовательные оставшиеся фазы

Работать **последовательно одним исполнителем в общих файлах**. Параллельная или дублирующая реализация API, модели, UI или 1С в том же worktree запрещена: она создаст конфликтующие контракты и потерю незакоммиченной работы. После каждого законченного этапа — тесты, `git diff --check` и отдельный понятный локальный коммит.

1. **Закончить CRM API и его тесты (текущий этап).** Добавить только нужные `/api/crm` маршруты поверх `CrmRepository`: tabs, список/карточка, создание локального лида, личные контакты/события/напоминания, перемещение, admin-archive/restore и audit. Owner ID брать из сессии; для admin требовать явный owner ID; проверять это на прямых запросах. Существующий `/api/clients` пока не ломать. Доработать `tests/test_crm_api.py`, затем коммитить API и его тесты вместе.
2. **Завершить серверные инварианты.** Контракты назначения/снятия назначения, удаление локальной карточки, архив, версии, разрешённая палитра, точная перестановка между соседями и запись истории должны соответствовать плану. Не выдавать текущую `position` за законченную DnD-семантику.
3. **CRM UI.** Новый `/crm` в текущем shell: «Клиенты 1С», «В работе», пользовательские вкладки, таблица/карточка/поиск/фильтры, контекстное меню перемещения и метки. Разделить общие реквизиты компании и личные контакты. Админский переключатель всегда показывает, чья CRM открыта, отменяет старые запросы и не подменяет сессию.
4. **История, напоминания, удаление.** UI событий и звонков, напоминания в открытом приложении и при входе, admin-only обратимое удаление/восстановление с подтверждением и аудитом. Не менять чужие напоминания при просмотре admin.
5. **Порядок, цвета и Excel.** DnD с insert-line/autoscroll/Escape/«Выше/Ниже», отключение вне полного «Мой порядок», optimistic rollback/конфликт. Ровно 12 ключей палитры + `null`; серверная XLSX-выгрузка `all`/`tab`, листы «Клиенты»/«Контакты», owner isolation, порядок, цвета и защита от формул.
6. **1С.** Сначала read-only проверить OData metadata, город/сайт, ETag/If-Match и права. Затем явное создание/связывание, постоянная очередь, snapshots, retry, идемпотентность неизвестного POST и field-level конфликты на fake 1С. Не включать автоматический PATCH без подтверждённой безопасной условной записи. Личные контакты, комментарии, звонки, напоминания, вкладки, цвета и порядок в 1С не передавать.
7. **Приёмка.** Временная БД, fake 1С, два пользователя и админ, прямые API-проверки, XLSX, UI на обычном/узком экране, существующие clients/documents/orders/КП. Затем `npm ci`, lint, `npx tsc --noEmit`, node tests и `npm run build` из `sm-techno-web`; запуск только на `127.0.0.1:8012` + `3012` с `BACKEND_API_BASE_URL=http://127.0.0.1:8012`.

## 8. Непроверенные внешние условия и безопасность

- Реальная OData доступность, metadata, поля города/сайта, ETag/If-Match и права записи конкретного пользователя 1С не подтверждены.
