# Разработка и выпуск

`main` — единственная постоянная линия разработки и интеграции. Наличие commit в main не означает, что он развёрнут или является стабильным релизом. Постоянной develop нет.

## Новая задача

В чистой отдельной копии (не в чужом рабочем дереве):

```powershell
git fetch origin
git switch -c codex/<задача> origin/main
```

Проверить изменения, открыть PR в main, дождаться реально выполненных обязательных проверок и независимого ревью по правилам проекта. Не обходить красные проверки. Для срочного исправления действует тот же порядок. Не force-push main.

Команды и изоляция перечислены в [README](../README.md) и [AGENTS](../AGENTS.md). Изменения схемы, контрактов API и 1С требуют отдельного плана; остатки, резервы, заказы, документы и Excel проверять особенно внимательно.

## Завершённые ветки и архив

После включения PR проверять отсутствие активной работы, открытых PR и внешних зависимостей имени ветки. Для сохраняемого состояния создать аннотированный тег `archive/<дата>/<исходная-ветка>` на явном проверенном SHA, с SHA, датой, исходной веткой и основанием в описании. Это не релиз и не GitHub Release. Не перезаписывать теги, не публиковать все refs массово.

Удаление remote-ветки допустимо только после проверки backup, опубликованного разыменованного тега, ancestry к текущему main, неизменности ожидаемого SHA и отдельного согласования. Использовать точечный expected-SHA/lease для удаления; локальную работу пользователя сохранять.

Восстановление ссылки в чистой копии:

```powershell
git fetch origin tag archive/<дата>/<ветка>
git switch -c codex/recovered archive/<дата>/<ветка>^{commit}
```

Публикация восстановленной ветки — отдельное решение с проверкой deploy-триггеров.

## Выпуск и деплой

Отдельно согласовать точный SHA из main, контур, резервное копирование данных и способ доставки. Только тогда готовить релизный тег vMAJOR.MINOR.PATCH и выполнять утверждённый runbook. Архивные теги не заменяют релизные. Не путать Git merge, изменение ссылки и обновление работающего приложения.

[Внешние зависимости и фактические ограничения](deployment-source-of-truth.md). До merge необходимо исключить неразрешённый автоматический production-деплой. Красный/неполный CI и непроверенный серверный SHA блокируют выпуск.
