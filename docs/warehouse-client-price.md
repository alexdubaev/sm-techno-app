# Склады в клиентском прайсе

План подтверждён владельцем 2026-11-02. В «Работа с прайсом → Локальные склады»
администратор управляет переключателем «Включать в клиентский прайс».
Настройка общая для сотрудников; по умолчанию все склады включены.
Сохранение выполняется сразу. Пока оно не подтверждено сервером, отображается
прежнее значение и статус «Сохраняется…»; повторное действие блокируется без
потери клавиатурного фокуса. Ошибка показывается рядом с переключателем.

Отключённый склад исключается на сервере только из новых клиентских прайсов.
Явный выбор его ID при выгрузке не обходит настройку. Товар с остатками на
нескольких складах остаётся в файле со строками разрешённых складов и их
количеством/ценой. Товары только на исключённых складах не возвращаются через
каталожную строку без склада, в том числе при нулевом остатке. Обычные
каталожные позиции без остатков сохраняют прежнее поведение.

Внутренние остатки, полный складской снимок, расценки и КП работают как раньше.
Активность склада (`is_active`), данные и интеграция с 1С не изменяются.

## API и хранение

- `GET /api/warehouses` дополнительно возвращает `includeInClientPrice`.
- Создание и переименование возвращают актуальный флаг в существующем ответе.
- `PATCH /api/warehouses/{id}/client-price` принимает ровно
  `{"includeInClientPrice": true|false}` и возвращает `{"warehouse": ...}`.
- Изменение требует существующей роли администратора: без сессии 401, у обычного
  сотрудника 403. Некорректное тело — 422, отсутствующий/неактивный склад — 404.

Используются отдельные ключи `warehouse_client_price:<id>` существующей
`app_settings`, со значениями `1`/`0`. Новых колонок и миграций нет. Отсутствие
ключа означает включение. Независимые переключения не перезаписывают один общий
список. Переименование, импорт и перезапуск сохраняют выбор. Общая форма
системных настроек не читает и не перезаписывает этот служебный префикс.

## Проверки и выпуск

Реальные XLSX, сохранение после импорта/переименования/перезапуска, права и
валидация проверяются в `tests/auth/test_warehouse_client_price.py` совместно с
существующими тестами прайса и складов. UI-тест проверяет ожидание ответа,
повторное нажатие, ошибку и успешный повтор. Короткий браузерный сценарий
проверяет переключение, перезагрузку, клавиатуру и размещение на экране.

Локальная стандартная пара портов была занята другим тестовым backend. Для
проверки использовался тот же npm launcher с очисткой окружения и приватной
игнорируемой конфигурацией на 127.0.0.1:13001/18001. Основная конфигурация,
изоляция тестов и существующий процесс не изменялись. Browser plugin отсутствует;
применён существующий Playwright-набор проекта.

Деплой — отдельная операция по конкретному main SHA, со свежей проверенной
резервной копией. Настройки остаются в БД при откате кода, но старый backend
этого флага не знает и выгружает все активные склады. Не объявлять такой откат
сохранением новой фильтрации; для его фактического применения учитывать этот
эффект отдельно. Уже скачанные Excel и сохранённые КП не переписываются.
