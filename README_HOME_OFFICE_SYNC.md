# Схема работы: офис и дом

Эта схема нужна, чтобы:
- код проекта редактировать и в офисе, и дома;
- рабочие данные не потерять;
- не смешивать базу и исходники в одном git-репозитории.

## Что синхронизируется через git

Через git отправляем только код:
- `stock_sync_api.py`
- папку `sm-techno-web`
- папку `scripts`
- папку `assets`
- служебные `.bat`, `.md`, `.txt`

## Что НЕ отправляется в git

В git не отправляем:
- `stock_sync.db`
- `backups/`
- `transfer/`
- `sm-techno-web/.env.local`
- `sm-techno-web/node_modules/`
- `sm-techno-web/.next/`

Это уже добавлено в `.gitignore`.

## Главный принцип

Код и данные синхронизируются отдельно:

1. Код:
   - через git
2. Рабочая база:
   - через файл `transfer\stock_sync_portable.db`

## Очень важное правило

Нельзя одновременно работать с одной и той же базой на двух компьютерах.

Правильный порядок:
- закончил работу на одном ПК;
- закрыл приложение;
- сделал `backup_db.bat`;
- перенес файл `transfer\stock_sync_portable.db`;
- на втором ПК выполнил `restore_db.bat`;
- только после этого запустил приложение.

## Как работать: офис -> дом

### В офисе перед уходом

1. Закрой приложение СМ Техно.
2. Запусти:
   - `backup_db.bat`
3. После этого появится актуальная переносимая база:
   - `transfer\stock_sync_portable.db`
4. Скопируй этот файл:
   - в облако;
   - на флешку;
   - или в общую папку.
5. Если менял код:
   - закоммить изменения;
   - отправь их в приватный git-репозиторий.

### Дома

1. Обнови код проекта:
   - `git pull`
2. Положи файл `stock_sync_portable.db` в папку:
   - `transfer\`
3. Запусти:
   - `restore_db.bat`
4. Запусти приложение:
   - `start_all.bat`

## Как работать: дом -> офис

Делаешь те же шаги в обратную сторону:

1. Закрываешь приложение дома.
2. Запускаешь:
   - `backup_db.bat`
3. Переносишь:
   - `transfer\stock_sync_portable.db`
4. В офисе кладешь файл в:
   - `transfer\`
5. Запускаешь:
   - `restore_db.bat`
6. Потом:
   - `start_all.bat`

## Если дома хочешь только пользоваться программой

Если дома не нужен перенос базы и не нужно менять код, проще работать через Tailscale:

1. Оставляешь офисный компьютер включенным.
2. Запускаешь там приложение.
3. Дома открываешь его по Tailscale-адресу.

Тогда база остается одна и переносить ее не надо.

## Первый git-репозиторий

Если репозиторий еще не создан, в папке проекта выполни:

```powershell
git init
git add .
git commit -m "Initial SM Techno project"
```

Потом привяжи удаленный репозиторий:

```powershell
git remote add origin <URL_ТВОЕГО_ПРИВАТНОГО_РЕПОЗИТОРИЯ>
git branch -M main
git push -u origin main
```

## Что делать, если восстановление не сработало

Проверь:

1. Приложение точно закрыто.
2. Файл лежит именно тут:
   - `transfer\stock_sync_portable.db`
3. В проекте есть доступ к файлу `stock_sync.db`.

## Безопасность

Так как в базе уже хранятся пользователи, логины и рабочие настройки, файл базы:
- не отправляй в публичные репозитории;
- не передавай посторонним;
- лучше хранить перенос в приватном облаке.
