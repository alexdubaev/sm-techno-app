# Схема работы: офис и дом

Эта схема нужна, чтобы:
- редактировать код и в офисе, и дома;
- не потерять рабочие данные;
- не смешивать исходники и локальную базу.

## Что синхронизируется через git

Через git отправляем код и служебные файлы:
- `stock_sync_api.py`
- папку `sm-techno-web`
- папку `stock_sync_web`
- папку `stock_sync_desktop` — используемый web-приложением общий слой БД, Excel и 1С;
  desktop-интерфейса в ней больше нет
- папку `scripts`
- папку `assets`
- `.bat`, `.ps1`, `.md`, `.vbs`

## Что не отправляется в git

В git не отправляем:
- `stock_sync.db`
- `backups/`
- `transfer/`
- `sm-techno-web/.env.local`
- `sm-techno-web/node_modules/`
- `sm-techno-web/.next/`

## Главный принцип

Код и рабочая база синхронизируются отдельно:

1. Код
   - через git
2. Рабочая база
   - через файл `transfer\\stock_sync_portable.db`

## Очень важное правило

Нельзя одновременно работать с одной и той же локальной базой на двух компьютерах.

Правильный порядок:
- закончил работу на первом ПК;
- закрыл приложение;
- сделал `backup_db.bat`;
- перенес файл `transfer\\stock_sync_portable.db`;
- на втором ПК выполнил `restore_db.bat`;
- только после этого запустил приложение.

## Как работать: офис -> дом

### В офисе перед уходом

1. Закрой приложение СМ ТЕХНО.
2. Запусти:
   - `backup_db.bat`
3. После этого обновится переносимая база:
   - `transfer\\stock_sync_portable.db`
4. Скопируй этот файл:
   - в облако;
   - на флешку;
   - или в общую папку.
5. Если менял код:
   - закоммить изменения;
   - отправь их в приватный git-репозиторий.

### Дома

1. Обнови код проекта:
   - `git pull`
2. Положи файл `stock_sync_portable.db` в папку:
   - `transfer\\`
3. Запусти:
   - `restore_db.bat`
4. Запусти приложение:
   - `start_all.bat`

## Как работать: дом -> офис

Те же шаги в обратную сторону:

1. Закрой приложение дома.
2. Запусти:
   - `backup_db.bat`
3. Перенеси:
   - `transfer\\stock_sync_portable.db`
4. В офисе положи файл в:
   - `transfer\\`
5. Запусти:
   - `restore_db.bat`
6. Потом:
   - `start_all.bat`

## Если дома нужен только доступ к приложению

Если дома не нужен перенос базы и не нужно менять код, проще работать через Tailscale:

1. Оставь офисный компьютер включенным.
2. Запусти там приложение.
3. Дома открой его по Tailscale-адресу.

Тогда база останется одна, и переносить ее не нужно.

## Безопасность

Так как в локальной базе уже хранятся пользователи, логины и рабочие настройки:
- не отправляй `stock_sync.db` в публичные репозитории;
- не передавай файл посторонним;
- лучше хранить переносимую копию в приватном облаке.
